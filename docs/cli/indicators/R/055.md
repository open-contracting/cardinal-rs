# Multiple direct awards above or just below competitive threshold (R055)

The total amount directly awarded by a buyer to a supplier is above the competitive threshold.

## Methodology

For each pair of buyer and supplier, the **total amount** is calculated as the sum of `/awards/value/amount` across all active awards in contracting processes whose `/tender/procurementMethod` is 'direct', for the same `/tender/mainProcurementCategory`. A buyer and supplier are flagged if there are multiple such awards and the total amount is greater than or equal to the **threshold**.

For each pair of procuring entity and supplier, the **total amount** is calculated the same as for buyers.

Awards just below the threshold are covered by the total: if a buyer splits a purchase into many direct awards that are each below the threshold, their total is above it.

:::{admonition} Example
:class: seealso

In Atlantis, a contract of 100,000 or more must be awarded through an open procedure.

The Ministry of Health directly awards three contracts of 40,000 each to MedSupply Ltd. Each contract is below the threshold. Their total of 120,000 is above the threshold. Therefore, the Ministry of Health and MedSupply Ltd. are flagged.
:::

:::{admonition} Why is this a red flag?
:class: hint

A corrupt buyer can avoid competition by splitting a purchase into many contracts below the competitive threshold, and directly awarding each to the pre-determined supplier.
:::

<small>Based on "Multiple direct awards above or just below competitive threshold" in [*Red flags in public procurement: A guide to using data to detect and mitigate risks*](https://www.open-contracting.org/resources/red-flags-in-public-procurement-a-guide-to-using-data-to-detect-and-mitigate-risks/).</small>

## Output

The indicator's value is the **total amount**, as a decimal. If an organization is flagged for multiple pairs, the indicator's value is the highest total amount.

If the ``--map`` command-line flag is set, the ``Maps`` key contains:

ocid_buyer_r055
: The buyer for each `ocid` whose award is in a flagged total for a buyer.

ocid_procuringentity_r055
: The procuring entity for each `ocid` whose award is in a flagged total for a procuring entity.

ocid_tenderer_r055
: The supplier for each `ocid` whose award is in a flagged total.

## Configuration

The indicator is not calculated unless a threshold is configured. Competitive thresholds differ by jurisdiction, so there is no default.

To set the **threshold**, add to your settings file, as a decimal in the same currency as the awards:

```ini
[R055]
threshold = 100000
```

To set the **threshold** per main procurement category (`/tender/mainProcurementCategory`), add a `[R055.main_procurement_category]` section to your settings file, in which the property name is a `/tender/mainProcurementCategory` value, and the property value is a decimal. For example, you can assign the thresholds per legislation:

```ini
[R055.main_procurement_category]
goods = 50000
services = 50000
works = 150000
```

A contracting process whose main procurement category has no threshold in this section uses the `threshold` property, if set. Otherwise, it is excluded.

To override the default procurement methods (`/tender/procurementMethod`), add to your settings file, as a pipe-separated list. For example, to also count awards from procedures in which the buyer invites a limited number of suppliers:

```ini
[R055]
procurement_methods = direct|limited
```

The default is:

```ini
[R055]
procurement_methods = direct
```

## Exclusions

An active award is excluded if:

- It is made to multiple suppliers
- Its currency is not the selected currency

A buyer and supplier are not flagged if there is only one such award: a single direct award above the threshold is often permitted under an exception, like an emergency.

To calculate a total over a period of time, like a calendar year, filter the input file by date before running the command.
